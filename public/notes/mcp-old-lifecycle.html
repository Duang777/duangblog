旧版 MCP：一条有状态的长连接

连接建立后先握手，双方各自记住对方，之后所有请求都跑在同一个会话上下文里。

客户端 ClientHost / LLM 应用
服务端 ServerMCP Server
① 握手
initialize协议版本 + 客户端能力 + clientInfo
──▶
◀──
InitializeResult服务端能力 + serverInfo
notifications/initialized握手完成，会话开始
──▶
◀──
Mcp-Session-Id 下发后续请求都要带上这个头
② 会话内的往返
tools/list · tools/call可按会话身份返回不同的工具集
──▶
◀──
服务端反向请求roots/list · sampling/createMessage · elicitation/create
回答反向请求服务端一直挂着这次调用的上下文等结果
──▶
GET + resources/subscribe开一条 SSE 长连收通知
──▶
◀──
推送通知 / ping 保活断线可用 Last-Event-ID 续传

状态藏在传输层隐式

会话 ID 绑定了版本、能力、订阅和进行中的调用，客户端看不见也管不了。

连接必须是双向的对等

服务端可以在处理一半时反过来调用客户端，前提是这条连接一直活着。

上云很别扭代价

同一会话必须落到同一实例，发版重启就会把所有客户端的会话一起丢掉。
